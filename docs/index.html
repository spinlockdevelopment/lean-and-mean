lean-and-mean

Short answers, minimal code, and an AGENTS.md that remembers every correction. Shorter sessions, less code nobody asked for, no repeat mistakes.

Install Guide and extras

The problem

Coding assistants say too much and build too much. Padded answers and unrequested helpers all need reading, review and upkeep. Every session also starts blank, so a mistake you fixed yesterday can come back today.

lean-and-mean writes a short instruction block into the project's root AGENTS.md. Codex loads that file directly. Claude Code loads it through a one-line CLAUDE.md that holds only @AGENTS.md. The block is then active every session, with no plugin code running.

How a session runs

What it does

Minimal code

A YAGNI ladder picks the smallest change that works. New code comes last.

Rules that stick

Every correction becomes one dated line under ## Rules. The file loads every session, so the mistake does not repeat.

Clean handoffs

/endsession saves Rules, the next task and the Todo list. Then it commits, pushes and stops.

Short answers

The answer comes first, with no filler. Sentences are short and active, about 80% ASD-STE100. A diagram or a page when that explains better.

The YAGNI ladder

Before writing code, the assistant stops at the first step that works:

  1. Only maybe needed later? Skip it and say so.
  2. Already in the project? Reuse it.
  3. In the standard library? Use it.
  4. Native to the platform (browser, OS, framework)? Use it.
  5. An installed dependency does it? Use it.
  6. Fits in one line? One line.
  7. Otherwise, the smallest new code that works.

Minimal never means careless. It never cuts input validation at trust boundaries, error handling against data loss, security, accessibility, or anything you asked for. Also:

  • Root cause. A bug is fixed at the shared place it comes from, not in every caller.
  • Labeled shortcuts. A deliberate shortcut gets a comment such as // lean: up to 1,000 rows, stream if larger.
  • One runnable check for logic with branches, loops, parsing, money or security.
  • A skipped note. After code, at most three lines say what was left out and when to add it.

An AGENTS.md that maintains itself

  • Rules. Each correction becomes one dated line. The cap is 15, so the list stays readable.
  • Next and Todo. ## Next names the next task. ## Todo is a short, prioritized backlog. History stays in git log.
  • Fixed layout. Operating Mode, Project & Stack, Commands, Architecture & Layout, Conventions, Done, Rules, Next, Todo, Notes & Pointers. Always in that order.
  • 250-line cap. The file is resent on every request. Overflow moves to linked agents-<category>.md files.

Commands

CommandEffect
/lean-and-mean:lean-and-meanCreate or review AGENTS.md. It refreshes the block, reorders sections, checks commands and paths, and prunes stale lines. Safe to rerun. The hook usually asks for it.
/lean-and-mean:lean-and-mean debtList every // lean: shortcut and its upgrade path. Changes nothing.
/lean-and-mean:endsessionSave Rules, Next and Todo, commit, push, then stop. When the work meets ## Done, it also runs those steps, such as a merge or a deploy. When it does not, Next says what remains. Details.

Codex uses $lean-and-mean and $endsession. A manual install gives the bare /lean-and-mean and /endsession.

The session-start hook

One short shell script runs when a session starts. It stays silent unless one of these is true:

  • The block is not in AGENTS.md. It prints the block for this session and suggests the create pass.
  • A review is due. The block is out of date, the file is over 250 lines, /endsession left a review flag, or CLAUDE.md is not the @AGENTS.md stub. The assistant then runs the full pass before your first task.

Extras

Optional parts, each covered in the guide.

Session band

A row above the Claude Code prompt: task checklist, End session button, auto /endsession at 5 minutes cache left, desktop countdown, cold-cache question.

Status line

extras/statusline.sh shows context use and a prompt-cache countdown in your terminal; you copy it in.

Advisor and effort

Settings that add a stronger reviewer model and set effort per session and subagent.

dashboard-builder

A subagent that keeps a self-refreshing progress page for long tasks.

explainer

A subagent that writes a local page with diagrams when an answer is too long for the terminal.

Why it pays off

4×cost per request over 400K context versus under 100K ($0.33 vs $0.08): restart at task boundaries
$1.21 vs $0.27median cost to resume after an hour away versus starting fresh; the worst resume measured, at 455K, was $8.79
$0.27median /endsession: a deliberate handoff instead of lossy compaction

Measured from 63 sessions and 5,197 requests (2026-09-03 to 2026-10-03) at API list prices, mostly on Opus 5, whose cache reads cost $0.50; on Opus 5.5 at $0.20 the absolute figures are lower. Every tool call resends the whole context, so cost scales with requests × context size. See why sessions should be short for the full model.

Install

Claude Code

claude plugin marketplace add spinlockdevelopment/lean-and-mean
claude plugin install lean-and-mean@lean-and-mean

Restart Claude Code. Then run /lean-and-mean:lean-and-mean once in each project. It writes AGENTS.md and the CLAUDE.md stub. Until then, the hook loads the block each session and reminds you.

Codex

codex plugin marketplace add spinlockdevelopment/lean-and-mean
codex plugin add lean-and-mean@lean-and-mean

Start a new session at the project root. Trust the SessionStart hook when prompted. Then run $lean-and-mean once.

No plugin support, or want bare command names? See manual install.

Turning it off

Disable the plugin and delete the ## Operating Mode section from AGENTS.md. The block lives in the file, so disabling alone is not enough.

Raw instructions

The plugin is plain text the model follows:

  • operating-mode.md — the block written into AGENTS.md
  • lean-and-mean/SKILL.md — setup, review and file structure
  • endsession/SKILL.md — the session handoff
