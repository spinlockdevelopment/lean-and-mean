The YAGNI ladder

YAGNI means "you aren't gonna need it". Before writing code, the assistant stops at the first step that works:

  1. Only maybe needed later? Skip it and say so.
  2. Already in the project? Reuse it.
  3. In the standard library? Use it.
  4. Native to the platform (browser, OS, framework)? Use it.
  5. An installed dependency does it? Use it.
  6. Fits in one line? One line.
  7. Otherwise, the smallest new code that works.

Minimal never means careless. It never cuts input validation at trust boundaries, error handling against data loss, security, accessibility, or anything you asked for. Also:

  • Root cause. A bug is fixed at the shared place it comes from, not in every caller.
  • Labeled shortcuts. A deliberate shortcut gets a comment such as // lean: up to 1,000 rows, stream if larger: the limit, then what to do past it. /lean-and-mean:lean-and-mean debt lists them.
  • One runnable check for logic with branches, loops, parsing, money or security.
  • A skipped note. After code, at most three lines say what was left out and when to add it.

AGENTS.md

One file holds the rules, the next task and the project facts. Codex loads it directly; Claude Code loads it through a CLAUDE.md that holds only @AGENTS.md.

  • Rules. Each correction becomes one dated line. The cap is 15, so the list stays readable.
  • Next. ## Next names the next task, then a backlog sorted P1 to P3. History stays in git log.
  • Fixed layout. Operating Mode, Project & Stack, Commands, Architecture & Layout, Done, Rules, Next, Notes & Pointers, always in that order. A sub-project can keep its own AGENTS.md in the same layout.
  • 250-line cap. The file is resent on every request. Overflow moves to linked agents-<category>.md files.

/endsession

The last message of a session. It turns this session's mistakes and failed approaches into Rules, rewrites ## Next and its backlog, flags a full review for the next session if the project's layout or commands changed, then commits and pushes, opening a PR when the branch is a feature branch or the default branch is protected. It never force-pushes. Then it prints a short summary of what was done, what was updated and what comes next. Then it stops.

  • Hard stop. Anything you pass that looks like a task is written under ## Next, not done. The model never invokes it on its own.
  • One question round. It asks once, up front, about at most three deletes that would remove a Rule or P1 Next item it can't judge. Clearly stale entries are dropped without asking. It never asks whether to commit or push: running it is the yes.
  • One memory. In Claude Code, project feedback and project entries from built-in auto memory are moved into Rules or Next, then deleted, so the committed AGENTS.md is the single place lessons live. user and reference memories are left alone.
  • Light on purpose. Context is largest at the end of a session, so the full AGENTS.md review waits for the next session's fresh, cheap context. /endsession only leaves a <!-- lean-and-mean: review --> flag.
  • Definition of done. AGENTS.md has a ## Done section listing what finished means for this project, with exact commands: say, merge the PR with gh pr merge --squash --delete-branch, then make deploy-staging. It defaults to committed and pushed. When the session's work is complete (what you asked is finished, the project's tests pass, no open question), /endsession runs those steps in order after pushing, then deletes local branches already merged into the default branch with git branch -d. Otherwise, or when a step fails, ## Next opens with Not done: <what remains> — <why>, so the next session picks it up. It only runs commands written in ## Done or ## Commands, never a deploy it guessed. The Session Status Mod's timed auto end never ships.
  • Safe push. Files that look like secrets (.env, keys, credentials) are never staged; they are named in the summary. A push behind the remote stops without rebasing. Any other push failure gets one attempt, then Unpushed: <branch> — <reason> becomes the first line of ## Next.

The session-start hook

One short POSIX shell script runs when a session starts. Once the ## Operating Mode block is in AGENTS.md, the mode needs no hook, flag or per-turn reminder: the host loads the file natively. The hook only covers the gaps:

ConditionWhat it prints
Block missing from AGENTS.mdThe block itself, so the mode is active anyway, plus a nudge to run /lean-and-mean
Block differs from the plugin's current copy (plugin updated)An instruction to run the full /lean-and-mean pass before your first task, then re-read AGENTS.md: the new file replaces the copy the host loaded at start
AGENTS.md over 250 lines
/endsession left the review flag
Claude Code: CLAUDE.md is anything but @AGENTS.md
Claude Code: ~/.claude/statusline.sh missing or its version line oldA one-line suggestion to run /lean-and-mean:statusline
Anything elseNothing

The pass runs at session start, not in /endsession, because the context is small then and each call is cheap. The CLAUDE.md check is also the upgrade path: a 3.x project kept its block in CLAUDE.md, so the pass merges that file into AGENTS.md and writes the one-line stub. Anything added to CLAUDE.md later moves over the same way. A CLAUDE.local.md keeps working alongside the stub.

Why sessions should be short

Every tool call resends the whole context, so cost scales with requests × context size. In the maintainer's logs (63 sessions, Sept–Oct 2026, API list prices), a request over 400K context cost 4× one under 100K, and a resume after the one-hour cache expired cost a median 4.5× a fresh start. /endsession writes the handoff for a median $0.27. So end at task boundaries and before breaks.

Measured, not a billing model; actual costs depend on host, model and caching.

Session Status Mod

The Session Status Mod is a row above the Claude Code prompt. It is a mod: a plugin module of function hooks that runs inside the session. The code is hooks/register.tsx, with helpers in hooks/judge.ts. hooks/hooks.json lists it under modules. It is the only plugin code that runs on every turn.

It is Claude Code only and on by default. Turn it off in /config under Session Status Mod. Codex ignores it. It writes nothing to your project; its state lives in Claude Code's plugin storage.

exp. 42m
tasks 2/3   [ hide tasks ]  [ end session ]
  ✓ Fix the login redirect
  ✓ Add a test for it
  ☐ Update the changelog
  • Task checklist. After each answered turn, Haiku updates the list. It adds the tasks you asked for and ticks the ones the reply shows finished. It runs at low effort with an 8-second cap. A malformed reply keeps the old list.
  • Hide tasks. This button folds the list to its count, such as tasks 2/3.
  • End session button. It runs /lean-and-mean:endsession. If the command cannot run, it fills the prompt box with it instead.
  • Nudge. When every task is done, you get a toast and the End session button turns primary. Your next prompt then tells Claude to suggest /endsession first, once per finished list.
  • Reset. /clear empties the checklist and the cache timer.

The cache clock

The prompt cache lasts one hour. Each main turn restarts that hour. The mod tracks it and acts at two points:

  • Auto end. At 55 minutes, the mod runs /lean-and-mean:endsession auto. It commits and pushes, but auto means it never ships. It fires only if no turn is running and you sent a real prompt since the last /endsession. Any /endsession, typed, button or auto, disarms it until your next real prompt.
  • Countdown. The top line of the mod shows the time left, such as exp. 42m, in the terminal and the desktop app. It is green above 30 minutes, yellow above 15, orange above 10, and red after that.

The cold-cache question

After the hour, the next request resends the whole context at full price. So the mod asks before it sends a prompt into a cold cache:

  • Rehydrate sends the prompt. The whole context is resent once at full price.
  • Clear first does not send the prompt. After any /endsession, auto, button or typed, it fills /clear: Next is already in AGENTS.md. Otherwise it fills /lean-and-mean:endsession, so Rules and Next are saved before you clear.
  • Your prompt is not kept after Clear first. Retype it after /clear.
  • Dismissing the question sends the prompt. A cache miss is better than a lost prompt.

Explainer Agent

A subagent, Claude Code only, that writes .pages/<slug>.html: one self-contained page for an answer too long or too structural for the terminal. The Operating Mode block tells Claude to explain in the cheapest form that works: a sentence, then a diagram, then a page. Call it directly with @agent-lean-and-mean:explainer.

  • Answer first. A short summary on top, then sections, in concise, active sentences that broadly follow ASD-STE100.
  • Diagrams replace paragraphs. Flows, structures and comparisons are inline SVG with a text label. Tables carry options and trade-offs.
  • Style, asked once. On first use the agent replies STYLE?; Claude asks you for dark or light, dense or airy, and one accent colour. The agent saves it in its user memory.
  • Contained. No network requests; it can read the project but writes only .pages/, which it gitignores. It states only facts it was given or read, with paths. It has no shell access.

Install details

Claude Code. In the app, /plugin marketplace add spinlockdevelopment/lean-and-mean then /plugin install lean-and-mean@lean-and-mean does the same as the shell commands. Restart afterwards: the hook loads only at session start.

Claude Code, manual: copy skills/lean-and-mean/ and skills/endsession/ into ~/.claude/skills/, copy hooks/session-start.sh somewhere, and add the SessionStart entry from hooks/hooks.json to ~/.claude/settings.json, pointing at that script. Manual installs get the bare /endsession and /lean-and-mean.

Codex. To test unpushed changes, install from a local checkout:

codex plugin marketplace add ~/src/lean-and-mean
codex plugin add lean-and-mean@lean-and-mean

Codex reads .claude-plugin/marketplace.json; its plugin metadata is .codex-plugin/plugin.json. Installing does not authorize hooks: trust the SessionStart hook when prompted. Select the skill in the picker. Start Codex at the project root, the same scope the hook checks. Nested instruction files still apply and are not rewritten. Remove any AGENTS.override.md: Codex reads it instead of AGENTS.md. The hook needs a POSIX shell (macOS, Linux or WSL). See OpenAI plugin packaging.

Codex without plugin support: copy both skill folders into ~/.agents/skills/ and run $lean-and-mean yourself. The mode persists, but there is no automatic session-start review.

Turning it off. Disable the plugin and delete the Operating Mode block. Disabling alone leaves the rules active; deleting alone lets the hook suggest setup again.
